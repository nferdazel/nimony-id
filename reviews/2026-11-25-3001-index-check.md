# Index checking at `4ba90a7` — the three shapes that escape

Evidence for the open erratum row "Chapters 10 and 15 (runtime index checking)", dated 2026-11-25. The probe set
was run by the Head of Engineering at the book's pin on 2026-11-25; the editor re-ran the checked/unchecked pair
the same day. The programs live outside the repository, so they are reproduced here.

- Toolchain: `~/.local/opt/nimony/4ba90a7`, `nimony 0.6.3`, commit `4ba90a781b0b22d0821efaa153c129c37cef6143`.
- Command per program: `~/.local/opt/nimony/4ba90a7/bin/nimony c -r <file>`.
- Host: macOS arm64. Backend: C, the one every book sample uses.
- No chapter or sample was modified to produce this note.

## Result

| Program | Check present | Exit | Printed |
| --- | --- | --- | --- |
| `control_try_body`: variable index out of range inside a `try` body | yes | 1 | `index out of bounds: 5 notin 0..2` |
| `case1_try`: read in an `except` handler after the body rewrote the index | **no** | 0 | an integer, no diagnostic |
| `case2_assign`: store that runs a side-effecting `=destroy` | **no** | 0 | an integer, no diagnostic |
| `case2_field`: the same store through an object field | **no** | 0 | an integer, no diagnostic |
| `case3_copy`, `case3_dup`: store that runs a side-effecting `=copy` or `=dup` | **no** | 0 | an integer, no diagnostic |
| `case4_sink`: call passing a value to a `sink` parameter | **no** | 0 | an integer, no diagnostic |

The three shapes named by `nim-lang/nimony#3001` all reproduce at the pin. The plain read and a read inside a
`try` body are checked, so the drop is in the handler, not in the body.

The escaping programs read a value from behind the array (the array is all zeros), so the integer differs between
runs. The observed values on 2026-11-25 were `-1149602003135495191`, `-7998353421675430915`,
`-7998177568883414052`, `85899345925`, `1729382110768150521` and `-1149765456964734719`. What matters is the exit
code `0` and the absence of any diagnostic.

## control_try_body.nim — checked

```nim
import std/syncio
let a = [10, 20, 30]
var i = 5
try:
  echo a[i]
except:
  echo "caught"
```

```
index out of bounds: 5 notin 0..2
FAILURE: nimcache/c/<build>/control_try_body
exit=1
```

The bare `except:` never runs: an out-of-range read is a fatal panic, not a catchable `ErrorCode` raise.

## case4_sink.nim — unchecked

```nim

type D = object
  x: int

  g = 1000000000
```

## Catchability

`except IndexError:` does not compile: `IndexError` is an `ErrorCode` value, not a type (the compiler asks for
`except ErrorCode as e:` plus a test of `e == IndexError`). An out-of-range read never becomes an `ErrorCode`
raise, so no `except` clause reaches it. That is why Chapter 15, which teaches `try`/`except` over `ErrorCode`,
needs no change.
